# Конституция книги

> Контракт с читателем и ограничитель для автора.
> Claude Code читает этот файл перед каждым действием.

---

## Высший принцип: причинность, а не рецепты

**Это правило стоит над всеми остальными.**

Книга не даёт готовых рецептов — она объясняет причинность. «Делай так, так и
так» — справочник, его забывают через неделю, потому что в голове остаётся
список действий без опоры. «Это нужно делать, потому что иначе ломается вот это;
для того, чтобы решить вот ту задачу; из-за того, что до этого было вот так» —
это понимание, и его можно вывести заново.

> Инженер, который знает «почему», построит то, чего в книге не было. Техник,
> который знает только «как», встанет на первом же случае не из учебника.

Если в тексте появилось «надо», «следует», «правильно» без «потому что»
рядом — **это брак**, параграф переписывается.

## Что эта книга ЕСТЬ

- **История веба как история болей роста.** Каждая технология родилась как ответ
  на невыносимость предыдущего шага. Без этой истории текущие решения выглядят
  произволом; с ней — естественным шрамом от пережитого.
- **Мост от древних практик к технологиям.** Под каждой технологией лежит
  что-то старое, бытовое, понятное. К моменту, когда читатель слышит термин, у
  него уже есть готовая полка в голове.
- **Практикум:** к концу книги читатель собирает работающий сайт — сквозной
  пример «Между строк».
- **Учебник для взрослого новичка вне 1С-домена**: единственная книга серии, где
  предметная область не 1С.

## Что эта книга НЕ ЕСТЬ

- **Не справочник и не пересказ документации.** Документация уже есть; книга
  учит её читать.
- **Не цитатник спецификаций.** RFC и стандарты — не для новичка: идею да,
  формулировку нет.
- **Не курс по конкретному фреймворку.**
- Не книга о 1С. Параллели с 1С существуют только во врезках «А вот в 1С»,
  которые не-1С-читатель пропускает без потерь.

## Главный тезис

> «YouTube в частности и соцсети в общем — это наскальная живопись».

Не остроумная находка, а рабочий принцип: всё, что есть в вебе, отвечает на
потребности, которым десятки тысяч лет. Носитель новый — потребность древняя.

| Древняя практика | Что стало в вебе |
|---|---|
| Наскальная живопись | блоги, YouTube, TikTok, Инстаграм |
| Городская площадь, агора | форумы, Reddit, твиттер |
| Письмо в конверте с маркой | электронная почта |
| Доска объявлений | Авито, классифайды |
| Бланк требования в библиотеке | HTTP-запрос |

## Две линзы оптики

Каждая технология рассматривается через две линзы одновременно — они не
конфликтуют, а дают объём, как два глаза.

**Линза 1. Боль.** Откуда взялась технология. Несущая ось спины книги.

**Линза 2. Три читателя.** Для кого она делается. У веб-страницы три читателя,
и живой человек среди них последний по очереди:

1. **Поисковик — привратник.** Заходит первым, решает, увидят ли страницу вообще.
2. **Браузер — переводчик.** Решает не «быть или не быть», а «каким ты
   предстанешь»; может переврать.
3. **Человек — заказчик.** Последний в очереди, но первопричина всего.

Ключевой нюанс: **поисковик угождает не себе — он угождает своей модели
человека.** Угождая роботу качеством, угождаешь человеку через прокси; угождая
накрутками — обманываешь и робота, и человека, и в итоге проигрываешь. Человек
не ушёл с вершины пирамиды, он спрятался за посредников.

**Обязательная оговорка.** Это верно не для всех сайтов. Публичный магазин —
да, его судьбу решает привратник. Но внутренняя админка за логином,
корпоративный портал, веб-клиент 1С для склада — туда робот не ходит,
единственный читатель сразу человек. Не оговорить это — значит подставить
читателя-практика, который полгода будет оптимизировать SEO там, где SEO не
существует.

Линза встроена не отдельным модулем, а сквозным вопросом, который книга задаёт
снова и снова: **«ты это сейчас для кого пишешь — для робота, для браузера или
для человека?»**

## Главное соглашение о форме

**Советская педагогика как скелет, авторский голос и метафоры как плоть.**

Скелет держит форму: параграф — единица внимания; определение, пример,
упражнение; повторение и кросс-ссылки; контрольные вопросы; чёткая структура
модуля.

Плоть держит внимание: древний предок в начале, боль → решение вместо «вот вам
стандарт», живой голос, врезки «Соври мне», сквозной пример.

Одно без другого не работает: чистый скелет сух и его не дочитают, чистая
плоть весела, но не учит.

## Что автор не будет делать никогда

- Не писать «надо / следует / правильно» без «потому что».
- Не вводить больше трёх новых терминов в параграфе.
- Не оставлять параграф без задания — это была бы лекция, а не учебник.
- Не лезть в нюансы раньше времени: в первом упоминании HTTP никаких HTTP/2 и
  мультиплексирования.
- Не писать «как известно», «очевидно», «легко видеть»: было бы очевидно —
  читатель не открыл бы книгу.
- Не прятать цену решения: рецепт скрывает компромиссы, инженерное объяснение
  их вскрывает.

## Аудитория (кратко)

**Читатель:** взрослый новичок в вебе. Не идиот — просто не знает. Возможно,
1С-разработчик, которому веб достался соседней задачей; возможно, человек вовсе
без опыта разработки.

**Читатель НЕ:** практикующий веб-разработчик за справочником; человек, ищущий
пошаговый рецепт «как сделать сайт за выходные».
