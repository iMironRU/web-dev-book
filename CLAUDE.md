# Инструкции для Claude Code

Книга «Веб глазами древнего человека». **Спина проработана полностью, текста
нет:** 13 модулей, 88 параграфов, все в статусе `todo` — размечены frontmatter
(линза боли, древний предок, дельта сквозного примера, целевой объём) и
шестичастным скелетом.

Перед любым действием прочитай контекст:

- **`spec/constitution.md`** — высший принцип «причинность, а не рецепты», две
  линзы оптики, главный тезис. Если предложение выходит за рамки — откажись.
- **`spec/specification.md`** — для кого книга, метрики, типология заданий,
  стадии сквозного примера.
- **`spec/decisions.md`** — лог решений.
- **`docs/style-guide.md`** — канон серии плюс надстройка книги: шесть частей
  параграфа, врезки, чек-лист, отступления от ядра канона.
- **`docs/spine.md`** — спина книги: все модули и параграфы.
- **`docs/roots-and-pains.md`** — метод: корни и боли роста.

## Структура репозитория

```
chapters/
  NN_slug/
    NN-00_modul.md    ← заставка модуля (# Модуль N. Название)
    NN-MM_slug.md     ← параграфы

example/   ← код сквозного примера «Между строк», стадии по git-тегам
spec/      ← конституция, спецификация, решения
docs/      ← спина, метод, канон стиля
```

Frontmatter параграфа — расширенный, поля книги сохраняются:

```yaml
---
module: 1
paragraph: "01.01"
slug: ot-naskalnoy-zhivopisi
title: "Зачем человеку всё это: от наскальной живописи до YouTube"
status: todo            # todo | draft | review | ready
lens_pain: "Почему вообще появился веб"
lens_ancestor: "Пещера Альтамира → инстаграм"
site_stage: ""
example_delta: "—"
reading_min: 40
chars_target: 10000
---
```

`todo` — скелет размечен, текста нет. При написании переводить в `draft`.

## Высший принцип

**Причинность, а не рецепты.** Ни одна технология не вводится фразой «принято
делать так». Всегда: вот задача → вот почему прежнее решение её не тянет → вот
что придумали и какой ценой.

> Если в тексте появилось «надо», «следует», «правильно» без «потому что»
> рядом — это брак, переписать.

Где у решения есть цена — цена называется. Рецепт прячет компромиссы,
инженерное объяснение их вскрывает.

## Две линзы

**Боль** — откуда взялась технология. **Три читателя** — для кого она делается:
поисковик-привратник, браузер-переводчик, человек-заказчик. Сквозной вопрос
книги: «ты это сейчас для кого пишешь?»

Обязательная оговорка: робот ходит не везде. В админку за логином и в веб-клиент
1С он не заходит — там единственный читатель сразу человек.

## Шесть частей параграфа

Заход (древний предок) → Постановка боли → Решение → Разбор на «Между строк» →
Резюме (5–8 строк) → Закрепление (3 вопроса + 1–2 упражнения).

Объём: 8 000–12 000 знаков. Больше — это два параграфа.

## Команды

### `/book-write §NN.MM [тема]`
Порядок: конституция → спецификация → frontmatter параграфа (там уже заданы
линза боли, древний предок и дельта примера) → соседние параграфы → стиль.
Перевести `status` из `todo` в `draft`.

### `/book-analyze §NN.MM`
Конституция → спецификация → стиль → чек-лист из `docs/style-guide.md`.
Отдельно ищи: «надо/следует/правильно» без «потому что»; больше трёх новых
терминов; параграф без задания.

### `/book-plan модуль-N`
Уточнить состав модуля по `docs/spine.md`; решения — в `spec/decisions.md`.

## Что не делать

- Не писать «надо / следует / правильно» без «потому что».
- Не вводить больше трёх новых терминов в параграфе.
- Не оставлять параграф без задания.
- Не пересказывать документацию и не цитировать RFC.
- Не лезть в нюансы раньше времени.
- Не изменять `metadata.yaml` напрямую — только через `./book.sh`.
- Не генерировать длинные тексты без запроса — сначала предложи план параграфа.
